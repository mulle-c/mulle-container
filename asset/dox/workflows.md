# mulle-container Workflows

## Build System

This project uses **mulle-sde** exclusively. Never invoke cmake or make directly.

### Build

```bash
mulle-sde craft          # Build the library
mulle-sde craft --release # Release build
mulle-sde recraft        # Clean rebuild
```

### After Adding/Removing Source Files

```bash
mulle-sde reflect        # Regenerate cmake/reflect/ files
mulle-sde craft          # Then rebuild
```

### Clean

```bash
mulle-sde clean          # Remove build artifacts
mulle-sde clean all      # Deep clean including dependencies
```

## Testing

The `test/` directory is an **isolated mulle-sde project** with its own
dependencies. Always use `mulle-sde test` commands.

### Run Tests

```bash
mulle-sde test run                          # Run all tests
mulle-sde test run test/array/10_insert_in_range/test.c  # Run specific test
mulle-sde retest                            # Full rebuild + retest (picks up dependency changes)
```

### Enable Vibecoding for Tests

```bash
mulle-sde vibecoding on
```

This keeps `.test.stdout`, `.test.stderr`, `.test.ccerr` files alongside tests
and preserves `.exe` files for debugging.

### Test Structure

Tests are organized by component in `test/`:

```
test/
├── array/          # 10_insert_in_range, 20_struct_insert_in_range, ...
├── assoc/
├── map/pointer/
├── queue/struct/
├── range/
├── rangemap/       # 00_noleak, 10_add, 20_remove, 30_search
├── rangeset/       # 00_noleak, 10_add, 20_remove, 30_shift, 40_stress, ...
├── set/pointer/
├── sort/
└── stash/
```

### Writing a Test

```c
#include "include.h"  // pulls in all dependency headers

int   main( void)
{
   // 1. Setup
   // 2. Exercise the API
   mulle_printf( "result: %d\n", value);
   // 3. Cleanup (free everything to avoid leaks)
   return( 0);  // 0 = success
}
```

Rules:
- Use `mulle_printf` over `printf` when available
- Never print timestamps, pointer addresses, or anything that varies between runs
- Return 0 for success
- Create a `.stdout` file with expected output for regression testing
- Tests compile with `-DMULLE_TEST=1`

### Creating Expected Output

```bash
mulle-sde test run --golden-stdout test/path/to/test.c
```

## Development Workflow

### Adding a New Source File

Do **not** just create files manually. Use mulle-sde:

```bash
mulle-sde add src/path/to/new-file.c
mulle-sde reflect
mulle-sde craft
```

### Adding a Dependency

```bash
mulle-sde dependency add github:owner/repo
mulle-sde reflect
mulle-sde craft
```

### Checking Available APIs

```bash
mulle-sde api list                    # List dependency APIs
mulle-sde api show mulle-allocator    # Show specific API docs
mulle-sde api find symbol malloc      # Find symbol in headers
```

### Debugging

```bash
mulle-sde craft --debug               # Debug build
mulle-sde test run --valgrind test/path/to/test.c  # Run with valgrind
```

## Code Style Enforcement

Before writing any code, read the style guide:

```bash
mulle-sde howto show --keyword styleguide --keyword c
```

Key rules:
- 3 spaces indentation (no tabs)
- Allman brace style
- `return( expr);` with parentheses
- Variables declared at top of function, sorted alphabetically
- No initialization at declaration (with specific exceptions)
- `case` labels not indented relative to `switch`

## CMake Guidelines

| Path | Editable? | Notes |
|------|-----------|-------|
| `CMakeLists.txt` | Yes | High-level project settings |
| `cmake/` | Yes | Override modules by copying from `cmake/share/` |
| `cmake/share/` | No | Managed by `mulle-sde upgrade` |
| `cmake/reflect/` | No | Auto-generated by `mulle-sde reflect` |
