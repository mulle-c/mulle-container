## Project Overview

mulle-container is a C11 library of data structures: arrays, hashtables, queues,
sets, and range structures. All containers use `mulle_allocator` for memory and
support both stack and heap allocation. None are thread-safe.

**Version**: 10.1.0 | **Dependencies**: mulle-allocator, mulle-data


## Directory Structure

```

│   ├── pointer/                   # mulle_pointerarray (unmanaged void*)

│   └── struct/                    # mulle_structqueue
```

## Two-Tier Naming Pattern

Every data structure has two variants:

| Variant | Example | Stores allocator/callback | Use case |
|---------|---------|--------------------------|----------|
| Single underscore | `mulle_array` | Yes | Convenience — fewer args per call |
| Double underscore | `mulle__array` | No | Minimal overhead — caller passes allocator |

The single-underscore functions are thin inlines that delegate to the
double-underscore layer.


## Coding Style (Quick Reference)

- **3 spaces** indentation (no tabs)
- **Allman** brace style
- `return( expr);` with parentheses
- Variables declared at **top of function**, sorted alphabetically
- No initialization at declaration (exceptions: from function args, aggregate zero-init)
- `case` labels align with opening brace of `switch`
- Run `mulle-sde howto show --keyword styleguide --keyword c` for full details


## Function Naming Convention

```
[_][mulle[_]_]<container>_<verb>[_<object>]
```

| Prefix | NULL-safe | Asserts in Debug |
|--------|-----------|------------------|
| `mulle_foo_verb` | Yes | Yes |
| `_mulle_foo_verb` | No | Yes |
| `_mulle__foo_verb` | No | Yes |

### Key Verbs

| Verb | Meaning | Opposite |
|------|---------|----------|
| `init` / `done` | Setup / teardown | Paired |
| `create` / `destroy` | Heap alloc+init / done+free | Paired |
| `add` | Append element | — |
| `set` | Overwrite (no return) | — |
| `get` | Read by index | — |
| `remove` | Delete element | — |
| `find` | Linear search → index | — |
| `member` | Membership test → 0/1 | — |
| `reset` | Remove all, keep allocation | — |


## Container Selection Guide

| Need | Use |
|------|-----|
| Managed pointer array (copy/free callbacks) | `mulle_array` |
| Simple pointer array | `mulle_pointerarray` |
| Array of structs/floats | `mulle_structarray` |
| Fast key/value lookup (custom equality) | `mulle_map` |
| Fast key/value lookup (pointer equality) | `mulle__pointermap` |
| Membership testing (custom equality) | `mulle_set` |
| Membership testing (pointer equality) | `mulle_pointerset` |
| Ordered key/value pairs (< ~100 items) | `mulle_pointerpairarray` |
| Sorted key/value with binary search | `mulle_assoc` |
| FIFO queue (no realloc) | `mulle_pointerqueue` |
| FIFO queue for structs (stable pointers) | `mulle_structqueue` |
| Non-overlapping range tracking | `mulle__rangeset` |


## Testing

The `test/` directory is an **isolated mulle-sde project**. Always use
`mulle-sde test` commands, never `mulle-test` directly.

```bash
mulle-sde test run                    # Run all tests
mulle-sde test run test/path/test.c   # Run specific test
mulle-sde retest                      # Full rebuild + retest
```

### Writing Tests

```c
#include "include.h"

int   main( void)
{
   // setup, exercise API, print results with mulle_printf
   mulle_printf( "result: %d\n", value);
   // cleanup everything
   return( 0);
}
```

- Use `mulle_printf` over `printf`
- Never print addresses, timestamps, or varying data
- Create `.stdout` file with expected output
- Tests compile with `-DMULLE_TEST=1`
